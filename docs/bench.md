# 离线对照基准：窗口误差、归因一致率与真实规模耗时

> 本文件说明 `coldchain bench` / `scripts/bench_window.sh` 跑的那套基准：**比什么、怎么算、结论怎么读**。
> **公开数据集不是产品对接面**——它只用来量算法在真实遥测数值上的行为。
> 产品的真实对接面是院内记录仪 / 边缘网关（入站）与冷链台账、通知系统（出站）。

## 一、基准回答哪三个问题

| 问题 | 指标 | 门槛 | 为什么是这三个 |
|---|---|---|---|
| 越限窗口抽得准不准 | **窗口误差**（采样条数） | ≤ 1 个采样周期 | 窗口起止要能对着记录仪导出的表一条条核；差一条尚可解释，差十条就是另一场异常 |
| 规则基线归因靠不靠谱 | **归因 Top-1 一致率** | 无门槛，作对照基线读 | 后续模型归因（task 27–31）要与它逐条比；先得有一个站得住的数字 |
| 真实规模跑不跑得动 | **耗时**（秒） | ≤ 30 秒 | 40 万条记录是院内一个冷链点位几个月的量；跑不动就说明离线复算这条路走不通 |

## 二、数据集怎么读

### 2.1 数据集的真实形态

公开冷链数据集（VCC-CPLD）**每一行是一次运输的遥测快照**（一条 shipment 记录），
不是「一台设备连续采样」：同一个 `sensor_bundle_id` 的各行之间可能隔着几天，
也可能是完全不同的货物；`shipment_id` 同样不成序列（同一 shipment 的各行散落在几个月里）。

因此基准**不把它当成单点时序直接喂给规则层**，而是按**设定点工况**归成若干条可比流：

| 流 | 设定点 | 温区（容差 3℃） | 条数 | 采样周期 |
|---|---|---|---|---|
| `setpoint--70c` | -70℃（超冷） | -73~-67℃ | 89,074 | 240 秒（该工况记录稀疏，中位间隔 4 分钟） |
| `setpoint-5c` | 5℃（冷藏） | 2~8℃ | 356,529 | 60 秒 |

同一条流内的记录按原始时间戳升序拼接后喂给规则层。
**拼接流只用于量算法行为，不代表任何真实设备的连续时序**，
也不能拿它推「某台冰箱夜里几点升到几度」。

### 2.2 温区容差不是拍脑袋定的

基准的温区是「设定点 ± 容差」，容差默认值 3℃——这个数从数据集自己的标注里反推：

- 数据集用 `time_above_threshold_min` 标注「高于阈值」的记录；
- 这些记录相对设定点的偏差最小值是 **3.000119℃**，向下取整到两位小数得 **3.00℃**；
- 基准据此把冷藏流温区取成 2~8℃——与产品点位配置里的疫苗冷藏温区**同一个口径**。

取整用**向下取整**而不是四舍五入：四舍五入可能把门槛抬到越限行之上
（最小偏差 3.005℃ 时四舍五入得 3.01℃，那条 8.005℃ 的越限行会被算成「还在温区内」，
凭空多出一条 1 个采样周期的误差）。向下取整保证「被数据集标为越限的行，一定在温区外」。

容差与数据集自带阈值对不上时，`VerifyAnnotationTolerance` 直接报错——
**窗口误差失去可比性时要说出来，而不是让人以为「误差 0 就是准」**。

### 2.3 设备事件与成因标注怎么映射

| 数据集列 | 映射为 | 口径说明 |
|---|---|---|
| `door_open_count > 0` | 该采样带一条 `door_open` 事件 / 成因标注 | 数据集是**逐记录累计口径**，规则层是**逐采样事件口径**，两者不同，见下 |
| `power_outage_count > 0` | `power_loss` 事件 / 成因标注 | 同上 |
| `defrost_cycle_flag == 1` | `defrost` 事件 / 成因标注 | 同上 |
| `time_above_threshold_min > 0` | 该采样属「越限标注段」 | 窗口误差的真值 |
| `time_below_threshold_min` | 「低于阈值」标注 | **该列全为 0**：数据集没有这一侧的真值，相关窗口单列计数，不混进窗口误差 |

## 三、三项指标怎么算

### 3.1 窗口误差

1. 数据集标注位串切成连续段（每段是一次「高于阈值」的连续记录）；
2. 规则层在同一条流上抽窗口（双阈值迟滞，容差 3℃、迟滞带 0.5℃）；
3. 每条标注段与**重叠最多**的那条窗口配对：
   - 不用「窗口是否覆盖标注段首条」配对——边界差一条采样时窗口会整体挪开一格，
     首条就落在窗口外面了，那是 1 个采样周期的偏差，不是「没对上」；
   - 重叠为 0 才算没对上（算法把这段越限整个漏了）；
4. 窗口起点与标注段起点的偏差、终点与标注段终点的偏差，各自折算成「差了几条采样点」，
   取两者较大者作为该段的窗口误差。

### 3.2 归因 Top-1 一致率

- **分母**：窗口内数据集成因标注**唯一**的那些窗口（189 条）；
- **一致**：规则基线给的 Top-1 原因与该唯一标注相同；
- **命中口径**：Top-1 落在成因标注集合内（标注有多个时用）；
- 数据集**没有**成因标注的窗口（1,711 条）不进分母——没有真值可比，
  硬凑进去只会把一致率稀释成一个没有意义的数。

### 3.3 耗时

从**读文件**那一步起算（读那 270 MB CSV 占掉大头，只算指标计算等于把大头藏起来），
并在报告里分三段列出：读数、抽窗口、逐窗口归因。

## 五、结论怎么读（三条不许误读）

### 5.1 归因一致率 0.48 是口径差，不是算法错

数据集的开门 / 断电 / 除霜是**逐记录累计口径**（这一行之前开过几次门），
规则层的开门判据要求**观测范围内累计开门 ≥ 5 分钟**（门开 5 分钟以下不足以解释一次温升）。
两套口径本就不同，door_open 类的 Top-1 一致率天然偏低。

因此这条指标是**模型归因的对照基线**，不是及格线：模型归因上线后，
要拿同一个数据集、同一个分母再跑一遍，比的是「模型比规则基线强多少」。

### 5.2 基准不设最短越限门槛

数据集的越限标注粒度是 1 分钟，而产品按「至少持续 N 分钟」把单点越限判为短时波动。
门槛取 1 分钟时，1,866 段标注里只有 **9 段**能成立为正式窗口，其余全落进「短时波动」，
窗口就无从比对了。**基准要比的是窗口抽在哪，不是门槛该定几分钟**——
门槛由点位配置决定。报告里另有一行按产品门槛复算的结果
（`policy_windows_at_product_gate` / `policy_transients_at_product_gate`），说明同一批数据在产品门槛下会分成多少窗口、多少波动。

### 5.3 耗时的大头在抽窗口，不在读数

读数 0.76 秒、抽窗口 15.14 秒（占 95%）、逐窗口归因 0.01 秒。
原因在规则层：**每抽一条窗口都要重算一遍整段温升速率**，
该计算随「窗口数 × 采样数」增长（35 万条采样 × 1,867 条窗口 ≈ 6.6 亿次采样级操作）。

- 产品的实时路径每次只判一条 run 的采样段，量级远小于此，不受影响；
- 但**离线批量复算**（飞检前重跑几个月历史、跨点位批量出报告）要留意这条；
- 这条是基准跑出来的**真实发现**，后续要么把温升速率改成按扫描结果一次算好、
  要么给抽窗口加一道分片上限。

## 六、怎么复现

```bash
bash scripts/fetch_datasets.sh     # 取数 + 完整性校验（幂等：SHA256 命中即跳过下载）
bash scripts/bench_window.sh       # 跑基准（默认 --repeat 2 核对可复现）
bash scripts/bench_window.sh --check   # 只校验已落盘的报告
go test ./internal/bench/... -v    # 口径自检（含真实规模用例；数据集未取到时跳过）
```

报告落在 `data/bench_baseline.json`（运行时目录，不入库），字段与口径见上。
